# Step 2：GitHub Copilot Chat で文書を作成する

---

## 🎯 このステップのゴール

- Copilot Chat の基本操作を理解する
- プロジェクトの README を Copilot で生成する
- 仕様書・定義書を Copilot の助けで素早く作る

---

## 2-1：Copilot Chat を開く

VS Code で `Ctrl+Shift+I`（Mac: `Cmd+Shift+I`）を押すと、  
Copilot Chat パネルが開きます。

または、左のアクティビティバーのチャットアイコンをクリックします。

---

## 2-2：README を Copilot に生成させる

### まずは空の README を作成

VS Code のエクスプローラーで `README.md` を右クリック → **Open with Copilot Chat** または、  
新しいファイルを作って Copilot に書いてもらいます。

### Copilot Chat に指示してみよう

以下のプロンプトをコピーして Copilot Chat に貼り付けてみてください：

```
このプロジェクトは、セキュリティニュースの URL を入力すると
自動的に日本語の HTML 記事を生成するツールです。

Node.js で動作し、GitHub Copilot Skills を使ってインタラクティブに
URL を受け取ります。

この内容で README.md を日本語で書いてください。
含める内容：
- プロジェクトの概要
- 必要環境（Node.js 18以上、VS Code、GitHub Copilot）
- セットアップ手順
- 使い方
- ファイル構成
```

> 💡 **Copilot へのコツ**: 何を作るか・どんな技術か・何を含めてほしいかを明示すると精度が上がります。

---

## 2-3：仕様書（機能定義書）を作る

Copilot Chat で以下を試してみましょう：

```
このセキュリティニュース自動化システムの機能定義書を作ってください。

## システム概要
- ユーザーがセキュリティニュースのURLを入力する
- Copilot Skill が URL のコンテンツを解析する
- 日本語で要約した HTML 記事を自動生成する

以下の形式でまとめてください：
1. システム概要
2. 機能一覧（テーブル形式）
3. 入力・出力の定義
4. 技術スタック
5. 制約事項
```

生成された文書は `docs/specification.md` として保存してみましょう。

---

## 2-4：Copilot Chat の便利な `/` コマンド

Copilot Chat のチャット欄で `/` を入力すると、コマンド一覧が表示されます：

| コマンド | 用途 |
|---------|------|
| `/explain` | 選択したコードを日本語で説明する |
| `/fix` | 選択したコードのバグを修正する |
| `/tests` | テストコードを生成する |
| `/doc` | ドキュメントコメントを追加する |
| `/new` | 新しいファイル・プロジェクトを作る |

### 試してみよう

1. `scripts/generate-article.js` を開く
2. コードを全選択（`Ctrl+A`）
3. Copilot Chat で `/explain` と入力して Enter
4. コードの説明が日本語で表示される

---

## 2-5：インラインチャット（その場で編集）

ファイルを編集中に `Ctrl+I`（Mac: `Cmd+I`）を押すと、  
その場でチャット入力ができます。

```
例：
- 「このコメントを日本語で書き直して」
- 「エラーハンドリングを追加して」
- 「このロジックをもっとシンプルにして」
```

---

## 2-6：定義書のテンプレートを作る

Copilot に頼んで、このプロジェクト専用の定義書テンプレートを作ってもらいましょう。

Copilot Chat に入力：

```
このリポジトリの機能追加時に使う「機能定義書テンプレート」を
Markdown 形式で作ってください。

含める項目：
- 機能名
- 概要（1〜3行）
- 入力パラメータ（テーブル）
- 出力形式
- 処理フロー（箇条書き）
- エラーケース
- 完了条件（チェックリスト形式）
```

## 💡 Copilot Chat 活用のコツ

1. **具体的に指示する**: 「いい感じに」より「〇〇の形式で、△△を含めて」の方が精度が上がる
2. **コンテキストを渡す**: ファイルを開いた状態や、コードを選択した状態で聞く
3. **繰り返し改善**: 一発で完璧でなくていい。「もっと簡潔に」「日本語で」と追加指示する
4. **丸ごとコピーしない**: 生成された内容を理解してから採用する
